## Merge screen: ADD_ADD conflicts (keep one copy's row, or both)

Companion to the engine change that makes `ADD_ADD` resolve for real (engine repo, same
day). Before, the merge screen offered "Keep both" for a row both copies added, but the
choice had no effect on the output.

- **The card** shows the two added rows side by side, field by field, marking each field
  the copies disagree on with a "≠" (not colour alone), then the choices: Copy 1's row,
  Copy 2's row, or **Keep both rows**. Keep both reveals a key field per row (Copy 1's
  starts as the original key, Copy 2's as `KEY-B`), with a hint when the sheet has a
  composite key (parts separated by " / ").
- **Errors appear on the card straight away**, even while other conflicts are unanswered:
  `previewMerge` now validates the answers given so far (via `resolveMerge` on just those
  conflicts) and returns `problems` — e.g. `"INV-2" is already used by another row`,
  `Keeping both rows needs two different keys`. A problem blocks the download.
- **Stale previews can't land:** typing a key fires a preview per keystroke, so only the
  newest response updates the screen.
- Pure helpers `defaultKeepBoth` and `compareRows` (`features/merge/addAdd.ts`) with unit tests.

Tests: 26 unit tests (was 22) and 8 e2e (was 6). The new `add-add.spec.ts` builds three
workbooks with ExcelJS (the shipped fixtures have no ADD_ADD), uploads them through the real
file inputs, and checks: the side-by-side view and the "≠" marker; download blocked until
answered; keeping Copy 2's row; keep-both with a key clashing with the Original, with the
same key twice, then valid — and the downloaded file's rows, totals preview (600 + 500 + 700
= 1,800) and Merge Log sheet.

## Re-opening a merged file now works (engine reader fix)

The engine now keeps formulas saved without a calculated result (see the engine log for the
cause, the cost measurements and the tests). In the app this means the file SheetLens writes
for a merge can be dropped back into Compare without its formulas disappearing.

- New e2e (`merge.spec.ts`): merge the sample files, download the result, open the Original and
  the merged file in Compare, and check that no formula was reported as overwritten, the four
  widened totals appear as `→ =COUNTA(…)` (not "(blank)"), and the real edits show with their
  values. 9 e2e green (was 8); 26 unit tests unchanged.
- Gotcha recorded in the test: Playwright saves a download under an extension-less temp name,
  which the app's own file-type guard (FR-IN-02) rightly rejects - upload the bytes under a
  real file name.
- Noticed, not changed: the Original vs merged comparison shows a High finding for the deleted
  invoice because its number appears in the new "SheetLens Merge Log" sheet (the check scans
  other sheets for a removed key). Added to the publishing guide's checklist.
