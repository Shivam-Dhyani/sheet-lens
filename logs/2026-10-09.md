# 2026-10-09

## Increment 6 — SheetLens reports (M5): Excel + HTML report renderers

Built the two downloadable report renderers that consume the engine's report
model (`buildReportModel`), both running inside the Web Worker and lazily
imported so they never weigh on first paint.

- `src/reports/excel-report.ts` — `renderExcelReport(model) → ArrayBuffer` via
  ExcelJS (lazy `import('exceljs')`). Three sheet kinds shaped to
  `reference_report_prototype.xlsx` (FR-REP-01):
  - **Overview** — title, privacy line, Old/New file, "Rows matched by", and an
    "At a glance" block whose counts are `COUNTIF` formulas over the All Changes
    table (so the figures are auditable and recalc live), each caching the
    engine's exact count as its result.
  - **All Changes** — severity-ordered table (`# Risk Where Invoice/Row Column
    What changed Old New What it means`) with an autofilter, frozen header, and
    risk-coloured Risk cells.
  - **"{Sheet} (marked)"** — Status column + data columns; changed cells
    highlighted (high / edited / recalculated) carrying their previous value as
    a cell note; removed rows placed by `afterKey` and struck through. Colour is
    never the only signal (Status labels + a labelled legend).
  - Indian `₹`/lakh number formats; a formula-injection note (xlsx string cells
    are inert — see `docs/IMPLEMENTATION_NOTES.md`).
- `src/reports/html-report.ts` — `renderHtmlReport(model) → string`: one
  self-contained HTML file, strict CSP meta, inline styles + a tiny inline
  search/risk-filter script, print styles (A4 landscape). No external requests
  (G-3 / FR-PRV); all text escaped.
- `src/reports/filename.ts` — `SheetLens_{new}_vs_{old}_{yyyy-mm-dd}.{ext}`
  (FR-REP-04). `src/reports/download.ts` — Blob download helper.
- Worker (`buildExcelReport`/`buildHtmlReport`) now renders from the stored
  report model and transfers the `ArrayBuffer` back; `ComparePage` gained
  "Download Excel report" / "Download HTML report" buttons alongside Copy
  summary.

Tests: Vitest unit (`report.test.ts`) round-trips the xlsx (sheet set, COUNTIF
formulas + cached results, changed-cell notes, struck removed rows) and asserts
the HTML is self-contained; Playwright e2e now downloads both reports and checks
the FR-REP-04 filenames in real Chromium. Fidelity: the report generated from
the Sales Register fixtures recalculates in LibreOffice headless to the engine's
exact counts (High 4 / Medium 9 / Info 3, rows +2/−1, 4 hand-edits, 1 formula
overwrite). Build clean — ExcelJS (940 KB) and the renderers sit in lazy chunks;
the landing bundle stays 132 KB gzip.

Next app increments: merge UI (M6–M7) + patch download, setup screen
(low-confidence key), password dialog, settings/templates (Dexie), PWA polish.

## Increment 7 — SheetLens assisted merge UI + patch download (M6–M7)

Wired the engine's merge + patch pipeline into the app, end to end in the Web
Worker (base IR, plan and resolutions stay in the worker; the UI holds only the
lightweight plan).

- Worker/client: `planMerge(labels)` (returns the plan, or a `MERGE_NO_KEY`/
  `MERGE_XLS` reason for the empty state), `previewMerge(resolutions,
  extendTotals)` (impact rows + the exact total-formulas the extend toggle would
  change; gated until every conflict is resolved), and `buildMerge(...)`
  (`resolveMerge` → `buildMergeLog` → `applyMergePatch`, transferring the patched
  bytes back with the FR-MRG-11 file name, applied log, blocked ops and fidelity).
  `openFile` now records each slot's password so the Original's password can be
  kept on the output (FR-MRG-09).
- Store: merge slots (`base`/`a`/`b`), copy labels, plan, resolutions
  (conflict choices + unticked proposals + related-edit acknowledgement),
  extend-totals and keep-password toggles; every edit recomputes the impact
  preview from the worker.
- Landing: a working **Merge** mode — three drop zones (Original, Copy 1, Copy 2)
  with editable copy names, "Plan the merge", and "Try with sample files"
  (ORIGINAL/RAVI/PRIYA, FR-IN-09).
- `MergePage` (FR-MRG-02…09): conflicts listed first with a "N of M to resolve"
  counter and per-type controls — CELL (Copy 1 / Copy 2 / keep Original / type a
  value), RELATED_EDITS (either side / Original / both + acknowledgement),
  DELETE_EDIT (delete / keep with edits / Original), ADD_ADD (either / both);
  auto-changes grouped by row and pre-ticked with a source tag; the extend-totals
  opt-in listing the affected formulas; the before/after impact table ("updates
  when opened in Excel" for totals the browser can't compute); keep-password
  toggle when the Original was encrypted; and a one-click **Download merged file**
  that shows the applied count, blocked operations and the fidelity checklist.

Tests: Vitest for the FR-MRG-11 file name; a Playwright US-02 e2e (real Chromium)
that drops the three fixtures, asserts 5 auto-changes + 3 conflicts (CELL
INV-1003, RELATED_EDITS INV-1008, DELETE_EDIT INV-1019), resolves them, checks
the impact shows Total GST payable ₹2,29,272.32 with totals extended, downloads
`Sales_Register_Sep2026_ORIGINAL_MERGED_*.xlsx`, and confirms 8 changes applied
(5 auto + 3 resolved). The engine's own golden already recalculates that exact
output in LibreOffice to the expected Summary. Build clean; landing 136 KB gzip.

Phase-1 app is now feature-complete for the core flows (compare → results →
reports → merge → patched download). Remaining polish: setup screen
